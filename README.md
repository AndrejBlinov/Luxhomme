# AI-ассистент для анализа отзывов маркетплейсов

Автоматизированная система, которая анализирует отзывы покупателей, группирует их по темам, выявляет топ-жалоб с цитатами и отправляет еженедельную сводку в Telegram.

## 🚀 Установка и запуск

### Требования
- Python 3.10+ (проверено на 3.12 и 3.15)
- Git
- Telegram-бот (создать через [@BotFather](https://t.me/BotFather))
- API-ключ OpenAI (или другого LLM-провайдера)

### 1. Клонирование репозитория
```bash
git clone https://github.com/AndrejBlinov/Luxhomme.git
cd Luxhomme
```
### 2. Создание виртуального окружения
# Windows
```bash
python -m venv venv
```

# Mac/Linux
```bash
python3 -m venv venv
```

### 3. Активация окружения
```bash
.\venv\Scripts\Activate.ps1
```

### 4. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 5. Настройка переменных окружения
Создайте файл .env в корне проекта (или скопируйте из .env.example) и заполните его своими ключами

### 6. Запуск скрипта
python src/main.py

### Выход из виртуального окружения
deactivate

## 🏗 Архитектура решения

Подробная диаграмма для MVP (data/MVP.drawio.png)
Диаграмма для продакшена, на масштабирование (data/Prod.drawio.png)

**Поток данных:**
1. **Источник данных:** CSV-файл с отзывами (DATE, SKU, RATING, TEXT)
2. **Обработка:** Python-скрипт читает данные и отправляет в LLM (OpenAI GPT-4o)
3. **Анализ:** LLM группирует отзывы по темам, считает WoW-динамику, выбирает цитаты
4. **Доставка:** Результат форматируется в Markdown и отправляется в Telegram через Bot API

**Почему такой подход:**
- CSV вместо парсинга API маркетплейса: стабильность и воспроизводимость за 10 минут (API Ozon/WB требуют авторизации, могут меняться)
- LLM вместо ручной разметки: масштабируемость на десятки тысяч отзывов
- Telegram вместо email/дашборда: команда уже использует Telegram, порог входа нулевой


## 💼 Что сделаю иначе в продакшене

Текущий прототип намеренно сделан минималистичным (CSV → LLM → Telegram), чтобы уложиться в тайминг тестового задания и показать рабочую бизнес-логику. Для промышленной эксплуатации я бы перестроил архитектуру по принципу **Repository Pattern**:

### 1. Единое хранилище данных (PostgreSQL)
- Все отзывы (и из CSV, и из API маркетплейсов) попадают в одну таблицу `reviews` через ORM (SQLAlchemy).
- Код анализа работает с абстракцией `ReviewRepository`, не зная, откуда пришли данные. Это решает проблему, когда в прототипе логика импорта и анализа смешаны.

### 2. Разделение на модули (SRP — Single Responsibility Principle)
- `src/importer.py` — отвечает только за парсинг и нормализацию данных из разных источников.
- `src/models.py` — ORM-модель Review, единая для всех источников.
- `src/repository.py` — абстракция над БД (можно подменить на in-memory для тестов).
- `src/analyzer.py` — работает только с репозиторием, вызывает LLM.
- `src/reporter.py` — форматирует результат и отправляет в Telegram.

### 3. Автоматизация сбора
- Airflow/Cron-задача еженедельно дергает API Ozon/WB через `OzonAPIImporter` и складывает в БД.
- CSV-импортер остается для ручного тестирования и миграции исторических данных.

### 4. Хранение истории и тренды
- Каждая сводка сохраняется в отдельную таблицу `reports` со связью с периодом.
- Это позволяет строить тренды за квартал: "снизился ли негатив по SKU X после смены поставщика".

### 5. Триггерные алерты
- Если доля негативных отзывов по SKU превышает 30% за день — мгновенный алерт в отдел качества, не дожидаясь еженедельной сводки.

### 6. Тестируемость
- Благодаря Repository Pattern можно написать unit-тесты на `analyzer.py` с мок-репозиторием, не поднимая БД.
- Интеграционные тесты — с тестовой БД в Docker.

### 7. Мониторинг и аудит
- Sentry для отслеживания ошибок.
- Логирование вызовов LLM (входные промпты, выходные JSON, стоимость токенов) — для аудита затрат и маржинальности сервиса.


## 🔍 Валидация AI: как проверялась точность

Чтобы выполнить критерий "Качество разбора", я не стал слепо доверять первой выдаче LLM. 

**Методика проверки:**
1. Вручную разметил 10 случайных отзывов из тестового набора по темам.
2. Сравнил ручную разметку с результатом работы промпта.
3. **Первичная точность:** ~80% (AI иногда путал "проблемы с доставкой" и "брак упаковки" из-за контекстных слов).

**Что было исправлено:**
Я добавил в `src/prompt.txt` технику **Few-Shot Prompting** (конкретные примеры "текст → правильная тема"). Это подняло точность классификации до 100% на тестовой выборке.

**Что сделаю в продакшене:**
- Создам "золотой" датасет из 200+ размеченных отзывов для регулярного бенчмарка промптов.
- Добавлю метрики качества (precision/recall) в логирование.

## ❓ Вопросы к маркетингу до старта

Вопросы к маркетингу до старта
Перед началом разработки я бы задал стейкхолдерам следующие вопросы, чтобы решение било точно в цель:

1) Целевое действие: Что конкретно команда делает с этой сводкой? (Меняет карточку товара, работает с поставщиком, корректирует рекламу?) От этого зависит глубина детализации сводки, период среза (1 раз в день, в неделю, в месяц)

2) Критичность тем: Есть ли "красные флаги" (например, упоминания безопасности или аллергии), которые должны триггерить мгновенное уведомление, а не ждать периодного отчета?

3) Исторический контекст: Есть ли у нас уже размеченные исторические отзывы, которые мы можем использовать как примеры для калибровки промпта под нашу специфику?

4) Специфика в принципе. Что необходимо учитывать в промте и обработке данных с учетом Бизнес процессов компании, а так же специфики товаров ?

5) Метрики: Целевыфе показатели эффективности. Какие будем смотреть? Надо точное описание целевых показателей и их сроков
    Например:
        Сокращение времени аналитика на 2 часа в неделю
        Снижение процента возвратов
        Точечная проработка негатива, улучшение продукта и, как следствие увеличение NPS,CSAT продукта и снизить отток клиентов по Retention Rate
        понимание сильных сторон продукта, которое откликается у пользователя для качественной рекламной компании 
        и тд...

6) нагрузка и данные. Какой объем данных предполагается иследовать и как часто? Необходимо для определения железа и окружения для сервиса, а так же понимание количества токенов для AI на обработку
